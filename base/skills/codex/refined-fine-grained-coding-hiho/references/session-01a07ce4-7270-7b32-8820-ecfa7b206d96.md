## 改善後に期待する判断と避ける判断

以下は元の依頼と指摘から作った確認材料であり、実行済みのエージェント評価結果ではない。

| 条件 | 期待する判断 | 避ける判断 |
| --- | --- | --- |
| 同じ入口を提供する A と B がともに自分を最後に置くよう説明する。固定版では A は B も呼ぶが、B は A を呼ばない | 入口の選択方法と呼び出しの向きを確かめ、両処理が実行される順序を選ぶ | 後勝ちと分かった段階で、どちらを選ぶべきかの調査を終える |
| 別の入口だけを提供する C を末尾へ追加する | 対象の入口と呼び出し関係への影響を確認し、影響がなければ同じ順序制約を課さない | 「A は常に配列の最後」として C の位置を制限する |
| 新版では B が A の処理も呼ぶようになった | 新版の呼び出し関係と出力から順序を再判断する | 過去のプラグイン名と順序をそのまま固定する |
| 未整列の import とクラスを含む入力で、変更前のチェックが成功する | 実際の整列結果を見て処理が呼ばれているか調べ、変更後は両方の整列と整形後のチェックを確かめる | チェックの成功だけで問題を否定する、片方だけの復旧で両立を報告する |
