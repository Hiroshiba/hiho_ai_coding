| 権限と空ディレクトリを復旧する古い処理がある | 元の欠落原因、配布アーカイブ、採用版の展開と後続の受け渡しを照合する | 最新ツールなら不要と推測する、別経路のエンジンのchmodも削除する |
| CIは実行ファイル名を明示するが、ローカルでは省略する | 生成する名前と参照する名前を、明示・未指定の両方で比較する | CIが通るのでproductFilenameで実ファイル名を得られると判断する |
| モードの既定値をnoneにし、job共通のDIRが後続ビルドへ継承される | 各ビルドの設定読込を確認し、必要なstepだけへ渡す案も比較する | 後続stepの空文字上書きだけを必須とする、DIRだけでcopyになる中間仕様を残す |
| CIとローカルで配置経路が異なり、片方だけ配置先が変わる | 経路別の配置先と起動パスの基準を対応付け、影響条件を説明する | 全経路で不変と報告する、外部エンジンを使う開発実行まで壊れていると広げる |
| 先行変更を前提に、差分最小と必須の変更だけを求められた | 比較基準を分け、先行側で整理した処理を戻さず、追加案は5段階の理由とともに報告する | 先行変更もすべて追加差分に数える、推奨程度の整理や対策を混ぜる |
| 既存OSはworkflowで環境変数を設定・リセットし、stepのenvで一時パスを渡す | 新しいOSも同じ責務分担・渡し方・コマンド・条件順序へ揃え、差が必要な条件だけを残す | 変数名が同じなら一致とする、新しい側へ合わせて既存側も変更する |
| 1行の値を渡す前提で改行除去をやめ、専用ディレクトリも作らなくする | 不要なprintf・コマンド置換・export・rmdirを追い、役目を失ったものを除く | trだけ削る、親ディレクトリの削除を残す、別用途のコマンドも一律に削る |
| 判定関数は見つかったが、設定読込後の初期化に依存する | 判定対象と時点を確認し、標準処理へ任せる入力条件も調べる | 関数名だけで置き換える、CIで変わらなければローカルも不変とする |
| 直接envへ渡した過去の成功があり、今度は行単位の形式で引き継ぐ | 入力条件を再確認し、未確認の性質を前提と区別して、ダミー値で新しい経路とcleanup後を確かめる | 過去の成功で入力が1行だと断定する、空文字を未定義化とみなす |
| 特定のテキストファイルの配置理由をコメントにする | ファイルの種類・領域・OS・失敗理由を残して、配置制約を説明する | ファイル名と完全パスだけを繰り返す、「署名のため」まで抽象化する、別領域でも必ず失敗すると広げる |
| 配置先を作る処理が固定の接頭辞選択と連結だけで、同じ意図の利用先に空の接頭辞を使うOSもある | 意図を表す定数と連結も検討し、同じ配置意図の利用先で共用して、例外の配置は分ける | 関数名を長くするだけ、空だから同じ配置意図の参照を省く、例外も同じ配置へ移す |

既存の[設定順序とコメントの確認材料](session-01a07ce4-7270-7b32-8820-ecfa7b206d96.md)も引き続き使う。
型・関数の短縮は、制約を見直すために必要な理由コメントを削除する指示ではない。ビルド補助処理の削除も、同じ入口を持つプラグインの選択・呼び出しを追う既存規則を置き換えない。

## 採用範囲と確認の限界

型・関数・命名の照合、入力条件を直接読める構造、補完と特定APIの区別、成果物と設定の経路を追う判断を採用する。後半からは、同種処理の責務分担と具体的な書き方、削除に伴う周辺処理、配置の意図を表す名前とコメントを補った。
途中のZod案、DIRだけでcopyにする既定値、formatを避ける制約は、最終判断で変更されているため固定しない。最終の「既定値はnone」もこの配置設定の仕様であり、他の設定に一般化しない。
`refined-coding-hiho` の継続する判断基準の文書化や、`refined-codedesign-hiho` の版・根拠の照合は重複追加せず、今回の具体的な呼び出し・入力・成果物の確認へ適用範囲を絞った。
エージェント分担、Git操作、pushやCI待機中の連絡は、今回の実装用スキルに追加しない。
固定の一時パス、1行での登録、echoの使用は今回の周囲との一致を優先した採用判断であり、すべての入力や実行環境へ固定しない。名前の修正途中に使った `getPathNextToExecutable` も推奨名として残さない。

2026-09-09の追加点検では、指摘・採用案・ログの差分・関連する現行コードを照合し、上表と既存確認材料の文面を点検した。公式 `skill-creator` の `quick_validate.py` による形式検証にも通過した。
実際のCodexによる再実装、独立エージェント評価、入力検証の再実行、配布用ビルドや起動確認は行っていない。実装品質の改善を実測したとは扱わない。
